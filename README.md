# Подземка — банкетный зал в стиле лофт / андеграунд

Учебный проект по **SEO-продвижению**. Это готовый сайт на Django про банкетный
зал «Подземка» в Чите (ул. Курнатовского, 17): кирпичные своды, бетон, неон, а каждый зал оформлен
как станция метро.

Дизайн и логика сайта уже готовы. **С точки зрения SEO сайт сделан плохо, и это
сделано нарочно.** Ваша задача — найти и исправить ошибки, чтобы сайт был готов к
индексации в Яндексе и Google.

> По коду разбросаны подсказки. Ищите комментарии с пометками
> **`SEO-ЗАДАНИЕ`**, **`ПОДСКАЗКА`**, **`SEO-ВОПРОС`**.
> Проще всего искать поиском по проекту (в VS Code: `Ctrl+Shift+F`).

## Стек

- Python 3.10+

- SQLite: база `db.sqlite3` лежит в репозитории и уже заполнена
- Никакого фронтенд-сборщика: чистые HTML, CSS и JS

## Как запустить проект

### 1. Скачайте репозиторий

```bash
git clone <ссылка-на-репозиторий>
cd <папка-проекта>
```

### 2. Создайте и активируйте виртуальное окружение

**Windows (PowerShell):**
```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```
> Если PowerShell ругается на политику выполнения скриптов, выполните один раз
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` или используйте `cmd`:
> `.venv\Scripts\activate.bat`

**macOS / Linux:**
```bash
python3 -m venv .venv
source .venv/bin/activate
```

После активации в начале строки терминала появится `(.venv)`.

### 3. Установите зависимости

```bash
pip install -r requirements.txt
```

### 4. База данных

База `db.sqlite3` уже лежит в репозитории: в ней залы, меню, афиша, отзывы, FAQ
и учётка администратора. Создавать и заполнять её не нужно.

Когда будете добавлять поля в модели (например, `slug`), создайте и примените миграции:

```bash
python manage.py makemigrations
python manage.py migrate
```

**Если база сломалась**, её можно собрать заново:

```bash
python manage.py seed_demo --flush
```
Эта команда удалит и заново заполнит контент (залы, меню, афишу, отзывы, FAQ).
Если сломано всё совсем, удалите файл `db.sqlite3` и выполните
`python manage.py migrate`, а затем `python manage.py seed_demo`.

### 5. Вход в админку

В базе уже есть учебный администратор:

| Логин | Пароль |
|---|---|
| `admin` | `podzemka2026` |

> ⚠️ Это учебный пароль только для локального запуска. На настоящем сервере такой
> пароль недопустим: он опубликован в открытом репозитории. Свой администратор
> создаётся командой `python manage.py createsuperuser`.

### 6. Запустите сервер

```bash
python manage.py runserver
```

Откройте в браузере:

| Что | Адрес |
|---|---|
| Сайт | http://127.0.0.1:8000/ |
| Админка | http://127.0.0.1:8000/admin/ (`admin` / `podzemka2026`) |

### Автотесты

```bash
python manage.py test
```
Тесты лежат в `venue/tests.py`: проверяют, что все страницы открываются, форма заявки
работает, а акция и прошедшие события скрываются вовремя. Прогоняйте их после своих
изменений — и допишите тесты на свои SEO-доработки (подсказки в начале файла).

### Как проверить страницу 404 (и сайт «как в бою»)

Страница 404 из шаблона видна только при выключенном режиме отладки:

**Windows (PowerShell):**
```powershell
$env:DJANGO_DEBUG="0"; python manage.py runserver --insecure
```
**macOS / Linux:**
```bash
DJANGO_DEBUG=0 python manage.py runserver --insecure
```
(`--insecure` нужен, чтобы при `DEBUG=False` продолжала грузиться статика.)

### Частые проблемы

| Проблема | Решение |
|---|---|
| `python` не найден | Попробуйте `py` (Windows) или `python3` (macOS/Linux) |
| `No module named django` | Не активировано виртуальное окружение (шаг 2) |
| `no such table` | `python manage.py migrate` (шаг 4) |
| Сайт пустой, нет залов | База пустая или удалена: `python manage.py seed_demo` (шаг 4) |
| Не пускает в админку | Если поменяли пароль и забыли: `python manage.py changepassword admin` |
| `no such column` | Добавили поле в модель, но не сделали `makemigrations` и `migrate` |
| Порт 8000 занят | `python manage.py runserver 8080` |

# ЗАДАНИЕ

Приведите сайт в порядок с точки зрения SEO. Задания разбиты на блоки.
**Обязательные** нужно выполнить все, задания **со звёздочкой ⭐** дают дополнительные баллы.

Перед началом **проведите аудит**: пройдитесь по всем страницам, посмотрите исходный
код (`Ctrl+U`) и запишите найденные проблемы. Это пригодится для отчёта.

## Блок 1. Мета-теги (обязательно)

1. **`<html lang>`**: укажите язык документа в `templates/base.html`.
2. **Уникальный `<title>` для каждой страницы.** Сейчас везде просто «Подземка».
   - Длина примерно 50–65 символов, главный ключ ближе к началу, бренд в конце.
   - На странице зала title собирается **динамически** из данных зала.
3. **`<meta name="description">`** для каждой страницы, 120–160 символов,
   уникальный, с призывом к действию. На странице зала тоже динамический.
4. **`<link rel="canonical">`**: абсолютный URL текущей страницы.
5. **Мета-тег robots**: закройте от индексации служебную страницу бронирования
   (`noindex, follow`). Ответьте в отчёте, почему здесь `noindex` лучше, чем `Disallow`.
6. **Favicon**: `favicon.ico` или `.svg`, `apple-touch-icon`, `theme-color`.

> ⭐ Добавьте в модель `Hall` поля `meta_title` и `meta_description` (см. подсказку в
> `venue/models.py`). Если поля заполнены в админке, выводите их, если нет, генерируйте автоматически.

## Блок 2. Open Graph и соцсети (обязательно)

Сделайте так, чтобы ссылка на любую страницу красиво выглядела в Telegram и ВКонтакте:

- `og:title`, `og:description`, `og:type`, `og:url`, `og:image`, `og:site_name`, `og:locale`
- `twitter:card` (`summary_large_image`)
- `og:image` — **абсолютный** URL, картинка 1200×630 (PNG/JPG; SVG соцсети не понимают!)
- На странице зала в `og:image` должна быть картинка этого зала

Проверка: https://developers.facebook.com/tools/debug/ или отправьте ссылку себе
в Telegram (сайт должен быть доступен из интернета, например через ngrok).

## Блок 3. robots.txt (обязательно)

1. Создайте `templates/robots.txt` и подключите маршрут `/robots.txt`
   (подсказка в `podzemka/urls.py`).
2. Закройте от индексации: админку, страницу бронирования, служебные URL.
3. Добавьте директиву `Sitemap:` с **абсолютным** адресом карты сайта.
4. Файл должен отдаваться с `Content-Type: text/plain`.

Проверка: http://127.0.0.1:8000/robots.txt и
[анализатор robots.txt в Яндекс.Вебмастере](https://webmaster.yandex.ru/tools/robotstxt/).

## Блок 4. Карта сайта sitemap.xml (обязательно)

1. Подключите `django.contrib.sitemaps` (подсказка в `settings.py`).
2. Доделайте заготовку `venue/sitemaps.py`: статические страницы и все активные залы.
3. Подключите маршрут `/sitemap.xml`.
4. Решите, каких страниц в карте быть **не должно** (дубли, служебные).

> ⭐ Добавьте в `Hall` поле `updated_at` и отдавайте `lastmod`.

Проверка: http://127.0.0.1:8000/sitemap.xml и
[валидатор Sitemap в Яндекс.Вебмастере](https://webmaster.yandex.ru/tools/sitemap/).

## Блок 5. Структура и контент (обязательно)

1. **Заголовки**: на каждой странице ровно один `<h1>`, без пропуска уровней (h2 → h4).
   - На главной сейчас **два** h1.
   - В галерее h1 **нет вообще**.
   - На главной после h2 идут сразу h4.
   - Некоторые h1 слишком общие («Залы»), добавьте в них ключевые слова.
2. **Изображения**: у всех `<img>` должны быть осмысленные `alt`, а также `width`/`height`;
   картинкам ниже первого экрана добавьте `loading="lazy"`.
3. **Тексты ссылок**: замените «Подробнее», «Смотреть» на информативные анкоры.
4. **Внешние ссылки** в подвале: добавьте `rel="noopener"` (подумайте, нужен ли `nofollow`).
5. **Хлебные крошки** на всех внутренних страницах (заготовка есть на странице зала).

## Блок 6. URL и дубли (обязательно)

1. **ЧПУ**: залы должны открываться по адресам вида `/halls/depo/`, а не `/halls/1/`.
   Добавьте `slug` в модель (подсказки в `models.py`, `admin.py`, `urls.py`, `views.py`).
   То же для афиши: `/afisha/kviz-60-sekund/` вместо `/afisha/1/`.
2. **Старые URL не должны умирать**: `/halls/1/` должен отдавать **301-редирект** на новый адрес.
3. **Дубль главной** `/home/`: избавьтесь от него (301 на `/`).
4. **Страница 404**: создайте `templates/404.html` в стиле сайта, с навигацией.

## Блок 7. Микроразметка Schema.org (обязательно, JSON-LD)

1. **Организация**: `EventVenue` (или `LocalBusiness`) в `base.html`: название, адрес
   (`PostalAddress`), телефон, часы работы, координаты (`GeoCoordinates`), `sameAs` на соцсети.
   Не забудьте `legalName` (ИП). Все данные уже есть в `settings.SITE_INFO`, в шаблонах они доступны как `{{ site.* }}`.
2. **Хлебные крошки**: `BreadcrumbList`.
3. **FAQ**: `FAQPage` на главной.
4. **События афиши**: `Event` на странице события (`/afisha/<id>/`): `name`, `startDate`,
   `location` (`Place` с адресом), `image`, `organizer`, `eventStatus`.
   ⭐ Для регулярного события (зарядка каждое утро) — `eventSchedule`. Подсказки в `venue/models.py`
   и `templates/venue/poster_detail.html`.

> ⭐ `AggregateRating` по отзывам, `Menu`/`Offer` для банкетного меню.

Проверка: https://validator.schema.org/ и
[валидатор микроразметки Яндекса](https://webmaster.yandex.ru/tools/microtest/).

## Блок 8. Задания со звёздочкой ⭐

- **Посадочные страницы под форматы** `/events/svadby/`, `/events/korporativy/` со своим
  h1, текстом (от 1500 символов) и мета-тегами. Подберите под них семантику
  в [Яндекс Вордстате](https://wordstat.yandex.ru/).
- **Семантическое ядро**: соберите 30–50 запросов и распределите их по страницам
  (таблица «URL → запросы → title → h1»).
- **Скорость**: прогоните сайт через Lighthouse (DevTools → Lighthouse), исправьте
  замечания; картинки в WebP/AVIF, `<picture>`/`srcset`.
- **Яндекс.Метрика** с целью «Отправка формы бронирования».
- **Мета-теги подтверждения** для Яндекс.Вебмастера и Google Search Console.
- **Карта** на странице контактов уже вставлена, но грузится сразу: добавьте iframe `loading="lazy"` и `title`.
- **site.webmanifest**.
- **Картинка тамады** (блок акции, `templates/includes/promo.html`): фото весит ~1 МБ при
  размере 2560×1706. Сожмите его в WebP до ~100 КБ, добавьте `alt`, `width`/`height`,
  `loading="lazy"` и сравните Lighthouse до и после. Разметьте акцию через Schema.org `Offer`
  (`validThrough`).
- **Фото залов** (`static/img/hall-*.jpg|webp`) — в разнобой: JPG и WebP, от 768 до 2000 px
  по ширине, одно вертикальное. Приведите их к единому формату и размерам, сделайте `srcset`.
  Исходники назывались `1.jpg`, `2.webp`, `3.JPG`, `4.jpg` — чем такие имена плохи?
- **Картинка квиза** (`static/img/quiz-60-sekund.jpg`) весит ~2,5 МБ. Исходник назывался
  `60 секунд.jpg` — пробел и кириллица в имени файла. Чем это плохо и как назвать правильно?
